# 骑行食宿规划 LLM Agent

输入骑行起终点与三项预算，程序调用高德 Web 服务获得骑行路线，在实际骑行道路里程的 50%～66.7% 区间连续搜索午饭；每骑行 15～20 公里优先安排加油站、其次安排便利店或超市作为休息点；到达终点后优先推荐住宿，如能找到实际骑行道路距离不超过 3 公里的晚饭点，则附加到住宿方案中。

现在可以用一句自然语言输入完整需求。项目默认使用本机 Ollama 中的 `qwen3:4b`，通过结构化输出把文本转换为严格的 `TripRequest`，然后交给原有高德工具链执行。不需要 OpenAI 账号或 API Key，也保留了可选的 OpenAI 后端。

## 为什么这是一个 Agent 项目

当前版本是一个“LLM + 确定性工具”的混合 Agent：

1. LLM 理解用户的中文描述，提取起终点和三项预算。
2. Pydantic 结构约束模型输出，信息缺失时保留为 `None`，程序再向用户询问，而不是让模型猜测。
3. 地图工具执行地理编码、骑行路线和周边 POI 搜索。
4. 确定性代码计算道路累计里程、距离约束、去重和排序。
5. 输出路线概况和带理由的推荐，同时保留警告和中间结果便于调试。

这种分工非常重要：LLM 擅长理解语言，但不负责猜测地图数据。地图距离和预算约束仍由普通代码执行，更准确、更便宜也更容易测试。

## 实际道路里程如何计算

高德返回整条骑行路线的 `distance`，以及每个道路分段的 `step_distance`，单位都是米。

项目使用 `step_distance` 做累计求和，并根据路线长度动态设置搜索点，保证相邻搜索点的道路间隔不超过 4 公里，再利用所在分段的 `polyline` 定位坐标。因此，路线进度不是起终点经纬度的直线距离比例。

经纬度距离只在已经选中的单个道路分段内部使用，用来沿折线放置搜索点，不参与决定总路线进度。

```text

```

## 运行 LLM 版本（默认本地 Ollama）

首次使用先安装 Ollama，然后下载模型：

```bash
ollama pull qwen3:4b
```

确保 Ollama 应用正在运行。如果没有启动，可以在一个单独终端中运行：

```bash
ollama serve
```

在 `.env` 中保留高德 Key，并添加本地模型配置：

```text
AMAP_API_KEY=你的高德Web服务Key
LLM_PROVIDER=ollama
OLLAMA_MODEL=qwen3:4b
OLLAMA_HOST=http://127.0.0.1:11434
```

`OLLAMA_MODEL` 可以在以后换成其他已下载的模型。不要把 `.env` 上传到 GitHub；仓库中的 `.env.example` 只包含占位符。

```bash
source .venv/bin/activate
python llm_main.py
```

输入示例：

```text
我想从武威市天祝县达隆宾馆骑到张掖市七彩丹霞景区，午饭50，晚饭80，住宿250。
```

如果不想启动任何 LLM，仍可以运行原来的表单式版本：

```bash
source .venv/bin/activate
python main.py
```

如果以后获得 OpenAI API Key，只需把 `.env` 改为：

```text
LLM_PROVIDER=openai
OPENAI_API_KEY=你的OpenAI_API_Key
OPENAI_MODEL=gpt-6-astra
```

运行离线测试：

```bash
python -m unittest discover -s tests -v
```

`.env` 已被 `.gitignore` 忽略，不应上传到 GitHub。

## 排序规则与数据限制

- 推荐分由高德评分、参考消费和距搜索点距离组成，并输出推荐理由。
- 高德缺失评分或价格时，程序明确显示“暂无”，不会虚构数据。
- 酒店 POI 的 `cost` 是高德提供的参考消费，不保证等于某一天的实时房价。接入酒店预订平台前，结果只能作为初筛。
- 周边距离表示 POI 到路线采样点的距离，不等于用户实际绕行距离。后续可以为候选 POI 再调用一次骑行规划，计算真实绕行成本。
- Agent 优先选择终点附近的住宿，再围绕每个住宿搜索晚饭；随后用坐标直线距离做低成本预筛选，并调用高德骑行规划验证实际道路里程。找不到 3 公里内晚饭时，住宿仍会保留。
- 名称中含有“暂停营业”“已关闭”“停业”等状态的住宿或餐厅不会进入推荐结果。
- 休息点从上一个休息点重新累计道路里程，优先搜索之后 15～20 公里的加油站，其次搜索便利店或超市；候选应距原路线不超过 100 米，没有结果时放宽到 300 米，再没有则把搜索窗口延长到 20～30 公里。
- 如果 15～30 公里内仍未找到休息点，下一轮会紧接从 30 公里处继续搜索，不再跳过 30～45 公里路段；后续找到时，输出的间隔仍按上一个真实休息点计算。
- 休息点查询每隔最多 5 公里在路线创建搜索中心，使用 3 公里查询半径召回候选，再把候选投影回原路线，以高德道路累计里程和距路线距离做最终过滤。
- 同一组独立 POI 搜索最多使用 4 个并发工作线程，同时在客户端统一限制请求启动频率；高德客户端会对临时网络错误、非法 JSON 和 QPS 限流自动退避重试，并缓存同次运行中的相同请求。非关键 POI 请求失败时，Agent 保留已获得的结果并输出警告，不会让整份规划直接丢失。
